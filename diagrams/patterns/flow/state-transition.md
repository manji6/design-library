# 状態遷移

## 0 名前・一言・略図

状態遷移。一言で: 左に「誰が」、そこから右へ「どう変わっていくか」を箱と矢印でつなぐ図。

```
          +------+    +------+    +======+    +------+
 [主体] ─ | 状態1 | →  | 状態2 | →  #状態3# →  | 状態4 |
          +------+    +------+    +======+    +------+
                    ^
                 (注釈)                ＃＝強調
```

## 1 この図が答える問い

- 主な問い: 「この主体は、どんな状態を経て、どこへ至るのか」
- 読み終えた読者が持ち帰るもの: 変化の道筋と、その中で特に見てほしい1点

## 2 使う場面と使わない場面

使う場面: 素材に次がそろっている時。

- 変化する主体が1つに決まる（人、顧客、案件、データ、組織など）
- 主体の状態を3〜6個の段階に分けられ、順序がある
- 移行はおおむね一方向

手がかりになる言葉: 「〜になる」「〜を経て」「〜へ進む」「段階的に」「ジャーニー」「態度変容」

使わない場面（他へ振り分ける）:

- 主体がおらず、作業の順番が主題 → flow/process-steps
- 各段階に「何人残るか」という量が主役 → quantity/funnel
- 2時点の差だけを言いたく、途中の段階は不要 → compare/before-after
- 戻りや繰り返しで強化されることが主題 → flow/cycle

## 3 情報構造

主体Sが状態 s1→s2→…→sn を順に経る。各遷移 si→si+1 には、任意で「きっかけ・障壁・特記事項」が1つ付く。状態のうち1つ（多くても2つ）が、筆者が最も伝えたい焦点になる。

## 4 構成要素と役割

| 役割 | 情報としての意味 | 視覚表現 | 必須 | 目安 |
|---|---|---|---|---|
| 主体 | 変化する当事者。状態の並びの「持ち主」 | 左端のラベル（アイコンは任意） | 必須 | 1 |
| 状態 | ある段階で主体がどうなっているか | ボックス。短い名詞句に、補足を1行まで | 必須 | 3〜6 |
| 遷移 | ある状態から次の状態への移行 | 隣り合うボックスをつなぐ矢印。向き＝時間 | 必須 | 状態の数−1 |
| 注釈 | 特定の遷移で起きる特筆事項（きっかけ、障壁、離脱など） | その矢印から出る吹き出し | 任意 | 0〜2 |
| 強調 | 読者に最も見てほしい状態 | ボックスを背景で塗り、文字は背景に対して読める色に（具体色はデザイン側） | 任意 | 0〜1（最大2） |

## 5 配置の原則

- 主体は状態の並びの起点（左端）に置き、並び全体の持ち主だと分かる位置にする
- 状態は読む方向（左→右）に等間隔で1列に並べる。6個を超えるなら、折り返さずに状態をまとめる
- 矢印は隣り合う状態だけをつなぐ。飛び越しや戻りを描きたくなったら、8の分岐・循環か別パターンを検討する
- この図の矢印が意味するのは「遷移」だけ。因果や参照を同じ矢印で描かない
- 吹き出しは矢印の上（または下）にそろえ、どの遷移に付くかが一目で分かるようにする
- 強調は「塗り」に加えて色以外の手がかり（太字など）を最低1つ併用する。大きさや枠を同時に変えない

## 6 書き方のルール

- 状態ラベルの品詞と粒度をそろえる。行動（「サイトに来る」）と状態（「納得している」）を混ぜない。どうしても混ざる場合は、1つのボックスを「状態名＋その時の行動」の2行構成にする
- 注釈には「なぜ移るか／その間に何が起きるか」を書く。状態の説明は書かない（それはボックス側の役目）
- 強調は、本文で「ここが要点」と1文で言える状態にだけ使う

## 7 最小形と成立チェック

- 最小形: 主体1、状態3、遷移2。注釈と強調はなくても成立する（状態が2つしかなければ compare/before-after の方が適切）
- 成立チェック: 色、アイコン、塗りをすべて外し、白黒の箱と矢印だけにしても「誰が・どう変わるか」が読めること。強調は色以外の手がかりで残ること

## 8 バリエーション

### 並置比較（複数段）

- 追加される問い: 「条件が違うと、同じ主体の変化はどう違うか」
- 核との差分: 各段の左端に「条件」（時代、チャネル、セグメントなど）のラベルが付く。主体が共通なら主体は1回だけ書き、条件ラベルを段ごとに置く
- 対応する状態は縦位置をそろえる。片方にしかない状態は空欄にして「ない」ことを見せる。順番が入れ替わること自体が論点なら、そろえずに入れ替わりを見せる
- 強調は「段の間で違う箇所」に置く（ここでは強調が「差の指し示し」を担う）
- 段は2〜3まで
- 別パターンへの境目: 各段の遷移を読む必要がなく、差だけを言いたい → compare/before-after

### 分岐

- 追加される問い: 「どこで道が分かれ、それぞれどこへ行くか」
- 分岐点は1つ、分かれる先は2本まで（離脱と継続など）
- 別パターンへの境目: 分岐条件の判断そのものが主役 → flow/branching

### 循環

- 追加される問い: 「最後の状態がどう最初に戻るか」
- 別パターンへの境目: 回るほど強化されることが主題 → flow/cycle

## 9 近いパターンとの見分け

| パターン | 違い |
|---|---|
| process-steps | 箱が「やること」で、主体は書き手側。状態遷移の箱は「主体がなっていること」 |
| funnel | 箱の大きさ（人数や割合）に意味がある。状態遷移の箱は同じ大きさ |
| timeline | 横の位置が時刻・日付を表す。状態遷移は順序だけを表す |
| before-after | 2時点の差だけを見せ、途中の段階は描かない |

## 10 分解の問い

1. 変わっていくのは誰（何）か？ → 主体。2つ以上あるなら、並置比較か別の図
2. その主体は、どんな状態を順に経るか？ → 状態（3〜6個、粒度をそろえる）
3. 隣り合う状態の間で特筆すべきことは？ → 注釈（なければ付けない）
4. 読者に1か所だけ見てほしい状態はどれか？ その理由は1文で言えるか？ → 強調
5. 条件違いの比較が必要か？ → 必要なら並置比較へ

## 11 実例

検索エンジン時代と生成AIチャット時代の購買行動（本人のサンプルより）。

**素材の要旨**: 生活者の行動が、検索エンジン時代と生成AIチャット時代で変わった。特に、態度変容が起きる場所がサイト内からAIの回答内へ移っている。

**判定**: 状態遷移＋並置比較（2段）

- 主体（生活者）がいて、段階に順序がある → 状態遷移
- 段ごとの流れを読ませたうえで、違いを見せたい → before-after ではなく並置比較
- 人数の減り方は論点ではない → funnel ではない

**分解**

- 主体: 情報を探す生活者（2段で共通）
- 条件（段ラベル）: 従来＝検索エンジン ／ 現在＝生成AIチャット
- 段1の状態: 疑問を持つ → 検索して比べる → サイトに着地（ランディング） → 態度変容 → コンバージョン
- 段2の状態: 疑問を持つ → AIに質問する → 態度変容 → サイトに着地（ランディング） → コンバージョン
- 注釈:
  - 段1「着地→態度変容」: サイト内のコンテンツで説得される
  - 段2「質問→態度変容」: AIの回答の中で比較と推薦が済んでしまう
- 強調: 段2の「態度変容」（1つだけ）。理由: 態度変容がサイトに着く前に起きるようになった、というのがこの図の要点

**略図**

```
        [生活者]
従来    疑問 → 検索・比較 → ランディング → 態度変容 → CV
                                   ^(サイト内で説得)
現在    疑問 → AIに質問   → #態度変容#  → ランディング → CV
                       ^(回答内で比較と推薦が完結)
```

**判断メモ**

- 1段だけでも成立する（核）。2段にしたのは「態度変容の位置が入れ替わった」ことが論点だから。入れ替わりそのものを見せるため、ここでは状態の縦位置をあえてそろえない（並置比較の例外側）
- 元の図は「ランディング」「コンバージョン」（行動・接点）と「態度変容」（状態）が混在している。マーケティングのジャーニー図では慣用的なので許容するが、厳密にするなら2行ボックスにそろえる（6のルール）
- 強調を段1の態度変容にも付けると「違い」がぼやけるので、付けない
